## 1. 抽象接口模式（函数指针 + 结构体）

**这是你跟我写代码最大的差异点，也是整个架构的基石。**

### 1.1 这个模式解决了什么问题

你原来写代码的风格：

```c
// Foc.c 中直接调 HAL_I2C
uint8_t buf[2];
HAL_I2C_Mem_Read(&hi2c1, 0x6C, 0x0C, I2C_MEMADD_SIZE_8BIT, buf, 2, 50);
float angle = ((uint16_t)buf[0] << 8 | buf[1]) * (360.0f / 4096.0f);
```

这段代码的问题：
- FOC 控制器绑死了 AS5600 编码器
- 换编码器（比如换成 TLE5012 SPI）要改 Foc.c
- 要懂 I2C 才能看懂 Foc.c

**接口模式的做法：**

```c
// Foc.c 不知道什么 AS5600，它只跟接口打交道
float raw = sensor->read_angle(sensor->ctx);
//         ↑ 函数指针
//                           ↑ 上下文（谁实现的，谁提供数据）
```

### 1.2 四步法

#### 第①步：定义接口

接口文件只放函数指针结构体，不放任何硬件头文件。

**文件：`Bsp/Inc/angle_sensor.h`**

```c
#ifndef __ANGLE_SENSOR_H__
#define __ANGLE_SENSOR_H__

typedef struct AngleSensor_t AngleSensor_t;

struct AngleSensor_t
{
    /**
     * @brief  读取机械角度（0 ~ 360°）
     * @param  ctx : 实现方的上下文（通常是 I2C 句柄）
     * @return 机械角度（度）
     */
    float   (*read_angle)(void *ctx);

    void    *ctx;   /**< 上下文指针，如 &hi2c1 */
};

#endif
```

要点：
- 用结构体把**函数指针**和**上下文指针**打包在一起
- 注释写清楚每个指针参数的语义
- `void *ctx` 是万能钥匙——任何指针都能传

项目中一共 4 个接口文件：

| 接口文件 | 函数指针 | 用途 |
|---|---|---|
| `Bsp/inc/angle_sensor.h` | `read_angle` | 读角度 |
| `Bsp/inc/pwm_output.h` | `set_duty`, `enable`, `disable` | PWM 三相输出 |
| `Bsp/inc/nv_storage.h` | `read`, `write` | 非易失存储 |
| `Bsp/inc/observer.h` | `update`, `get_position`, `get_velocity` | 角度观测器 |

#### 第②步：实现接口

写一个 **.c 文件**，实现接口中定义的函数指针。

**文件：`Bsp/Src/angle_as5600.c`**

```c
#include "angle_as5600.h"
#include "i2c.h"

#define AS5600_ADDR      0x6C
#define AS5600_ANGLE_REG 0x0C

// 这个函数签名必须跟 angle_sensor.h 中的函数指针一致：
//   float (*read_angle)(void *ctx);
float AS5600_ReadAngle(void *ctx)
{
    I2C_HandleTypeDef *hi2c = (I2C_HandleTypeDef *)ctx;
    static float last_angle = 0.0f;
    uint8_t buf[2] = {0};
    uint16_t raw;

    if (HAL_I2C_Mem_Read(hi2c, AS5600_ADDR, AS5600_ANGLE_REG,
                         I2C_MEMADD_SIZE_8BIT, buf, 2, 50) != HAL_OK)
    {
        // I2C 读失败 → 返回上次有效角度，不产生角度跳变
        return last_angle;
    }

    raw = ((uint16_t)buf[0] << 8) | buf[1];
    last_angle = (float)raw * (360.0f / 4096.0f);
    return last_angle;
}
```

注意：
- 函数签名必须跟函数指针完全一致
- `ctx` 是 `void *`，用它之前要转型回真正的类型
- 这个文件可以包含 HAL 头文件（它是实现方，需要调硬件 API）

#### 第③步：工厂函数

工厂函数把函数指针和上下文粘到一起。

```c
// 还在 angle_as5600.c 中
AngleSensor_t AS5600_Create(I2C_HandleTypeDef *hi2c)
{
    AngleSensor_t sensor;
    sensor.read_angle = AS5600_ReadAngle;   // 填入函数指针
    sensor.ctx        = (void *)hi2c;       // 保存 I2C 句柄
    return sensor;
}
```

命名规范：`XXX_Create(参数) → 返回接口结构体`。

项目中所有工厂函数：

| 工厂函数 | 参数 | 返回答 |
|---|---|---|
| `AS5600_Create(hi2c)` | I2C 句柄 | `AngleSensor_t` |
| `PWM3Phase_Create(htim)` | TIM 句柄 | `PwmOutput_t` |
| `FlashStorage_Create(addr, magic, size)` | 地址/魔数/扇区大小 | `NvStorage_t` |
| `ObserverLuenberger_Create(cfg)` | 配置结构体指针 | `Observer_t` |

#### 第④步：使用接口

业务层通过函数指针调实现，完全不关心底层。

**文件：`App/Src/Foc.c`**

```c
// FOC_Init 中保存接口指针
foc->sensor   = sensor;    // 传入的是 AngleSensor_t *
foc->motor    = motor;     // PwmOutput_t *
foc->storage  = storage;   // NvStorage_t *
foc->observer = observer;  // Observer_t *

// 使用时通过函数指针调用
void FOC_UpdateSensor(FOC_t *foc)
{
    float raw = foc->sensor->read_angle(foc->sensor->ctx);
    //              ↑ 函数指针              ↑ 上下文
    foc->observer->update(foc->observer->ctx, raw);
    foc->mech_angle = foc->observer->get_position(foc->observer->ctx);
    foc->speed      = foc->observer->get_velocity(foc->observer->ctx);
}
```

### 1.3 换硬件要怎么改

假设你想把 AS5600（I2C 编码器）换成 TLE5012（SPI 编码器）：

```diff
// 只需要改 main.c 中的工厂调用，Foc.c/motor_ctrl.c 一行不动！

- AngleSensor_t sensor = AS5600_Create(&hi2c1);
+ AngleSensor_t sensor = TLE5012_Create(&hspi1);

  // 前提：TLE5012_Create() 返回的也是 AngleSensor_t
  // TLE5012_Create() 内部实现：
  //   static float TLE5012_ReadAngle(void *ctx) {
  //       SPI_HandleTypeDef *hspi = (SPI_HandleTypeDef *)ctx;
  //       // ... SPI 读代码 ...
  //       return angle;
  //   }
  //   AngleSensor_t TLE5012_Create(SPI_HandleTypeDef *hspi) {
  //       AngleSensor_t s;
  //       s.read_angle = TLE5012_ReadAngle;
  //       s.ctx = (void *)hspi;
  //       return s;
  //   }
```

换个板子（比如 STM32G4）同样道理——你只要保证新板子上的 BSP 层实现了这几个接口，APP 层不用改。

### 1.4 你可以在自己的项目中怎么用

```c
// 1. 定义接口
typedef struct {
    float (*read_temp)(void *ctx);
    void *ctx;
} TempSensor_t;

// 2. 实现 NTC 版本
float NTC_ReadTemp(void *ctx) { /* ADC 读 NTC */ }
TempSensor_t NTC_Create(ADC_HandleTypeDef *hadc) {
    TempSensor_t s;
    s.read_temp = NTC_ReadTemp;
    s.ctx = (void *)hadc;
    return s;
}

// 3. 实现 DS18B20 版本
float DS18B20_ReadTemp(void *ctx) { /* OneWire 读 */ }
TempSensor_t DS18B20_Create(...) { ... }

// 4. 业务代码中
void ControlTemp(TempSensor_t *s) {
    float t = s->read_temp(s->ctx);
    // 不管是什么传感器，都能用
}
```

```
└──────────────────────────────────────────────────────┘
```

### 2.2 铁律

```
APP 可以 include: DRV, BSP, LIB
DRV 可以 include: BSP, LIB
BSP 可以 include: LIB
LIB 不 include 任何非标准库头文件（只 include <stdint.h>, <math.h> 等）

反向禁止！
  DRV 不能 include APP
  BSP 不能 include APP 或 DRV
  LIB 不能 include APP、DRV 或 BSP
```

### 2.3 为什么这样分

| 场景 | 要改的层 | 不用动的层 |
|---|---|---|
| 换单片机（F103→F405） | DRV（HAL 调用不同） | APP, BSP(接口), LIB |
| 换编码器（AS5600→TLE5012） | BSP（新建实现文件） | APP, DRV, LIB |
| 换存储介质（Flash→EEPROM） | BSP（新建实现文件） | APP, DRV, LIB |
| 改 FOC 控制算法 | APP(Foc.c) | DRV, BSP, LIB |
| 移植到 PC 仿真算法 | LIB 直接复制 | — |

## 3. 工厂函数模式

工厂函数是一个"构造函数"，它把实现细节隐藏在内幕，返回一个已经配置好的接口结构体。

### 3.1 标准模板

```c
// 在实现文件（.c）的末尾
ReturnType_t XX_Create(参数)
{
    static XX_Ctx_t ctx;       // 静态存储——生命周期持续到断电

    ctx.param1 = param1;       // 存入参数
    ctx.param2 = param2;

    ReturnType_t obj;
    obj.func1 = XX_Func1;      // 填入函数指针
    obj.func2 = XX_Func2;
    obj.ctx   = &ctx;          // 上下文指向内部状态

    return obj;                // 返回结构体（栈上拷贝，轻量）
}
```

### 3.2 项目中 4 个工厂函数的对比

| 工厂函数 | 内部状态（ctx 指向什么） | 初始化工作 |
|---|---|---|
| `AS5600_Create(hi2c)` | 无内部状态，ctx 直接存 I2C 句柄 | 无（HAL 已经初始化好） |
| `PWM3Phase_Create(htim)` | 无内部状态，ctx 存 TIM 句柄 | 启动三路 PWM 通道 |
| `FlashStorage_Create(addr, magic, size)` | 存 Flash 地址/魔数/扇区大小 | 无（硬件已经初始化） |
| `ObserverLuenberger_Create(cfg)` | 存 l1/l2/Ts/x2_max/x1_hat/x2_hat | 清零所有状态初始化 |

### 3.3 你以后怎么用

```c
// 不管什么硬件，统一用一个工厂函数创建实例
// 所有配置都在这一个函数调用里完成
TempSensor_t temp = NTC_Create(&hadc1);
// 或者
TempSensor_t temp = DS18B20_Create(&huart2);

// 使用的时候完全一样
float t = temp.read_temp(temp.ctx);
```

## 4. 回调注册机制

### 4.1 解决的问题

你原来会在中断里直接写业务逻辑：

```c
// ❌ 原来的写法：修改业务逻辑必须进中断文件
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim) {
    Motor_Loop();           // 业务逻辑写死在中断文件里
    HAL_GPIO_TogglePin(...); // 测试代码也混在里面
}
```

### 4.2 现在的做法

**第①步：驱动层提供注册函数**

```c
// drv_tim.c
typedef void (*TIM_Callback_t)(void);  // 回调类型

static TIM_Callback_t user_callback = NULL;  // 静态保存回调指针

void TIM_RegisterCallback(TIM_Callback_t cb) {
    user_callback = cb;     // 注册就是把函数指针存下来
}
```

**第②步：中断只调回调**

```c
// drv_tim.c
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim) {
    if (htim == &htim1) {
        LED_Tick();                  // 硬件相关：LED 驱动
        // ...
        if (user_callback != NULL) {
            user_callback();         // → Motor_Loop()
        }
    }
}
```

**第③步：main.c 中注册**

```c
// main.c
TIM_RegisterCallback(Motor_Loop);    // 把业务函数地址传进去
```

**CAN 也是同样的模式：**

```c
// drv_can.c
static CAN_RxCallback_t rx_callback = NULL;

void CAN_RegisterRxCB(CAN_RxCallback_t cb) {
    rx_callback = cb;
}

// 中断中：
void HAL_CAN_RxFifo0MsgPendingCallback(...) {
    if (rx_callback != NULL) {
        rx_callback(id, data);  // → CANProto_RxCallback()
    }
}

// main.c
CANProto_Init(1);  // 内部会调 CAN_RegisterRxCB
```

### 4.3 好处

- **中断文件不变**：不管业务逻辑怎么改，`stm32f1xx_it.c` 和 `drv_tim.c` 不需要再改
- **可替换**：`TIM_RegisterCallback(Motor_Loop)` 换成 `TIM_RegisterCallback(Other_Loop)` 即可切换业务
- **可空检查**：`if (cb != NULL)` 防止未注册时调空指针

## 5. 消息总线模式

### 5.1 架构图

```
                    ┌─────────────────────────────────────┐
                    │          motor_msg.c                │
                    │                                     │
 CAN 数据流 ──────→ │  OnFrameReceived() → 解码 → 存储    │
 UART 数据流 ─────→ │  OnFrameReceived() → 解码 → 存储    │
                    │                                     │
                    │  PollCommand() ←── motor_ctrl 每 1ms │
                    │                                     │
                    │  TxStatus() ──→ CANProto_SendPayload │
                    │  TxStatus() ──→ UARTProto_SendPayload│
                    └─────────────────────────────────────┘
```

### 5.2 数据流详解

**接收路径（主机命令 → 电机控制）：**

```
① CAN 总线收到一帧
   → CAN1_RX0_IRQHandler
     → HAL_CAN_IRQHandler
       → HAL_CAN_RxFifo0MsgPendingCallback (在 drv_can.c)
         → rx_callback(id, data)    ← 注册的是 CANProto_RxCallback
           → MotorMsg_OnFrameReceived(MSG_CH_CAN, payload)
             → 解码 payload → 存到 g_cmd
               → 设置 g_new_frame = 1

② 或 UART 收到一帧
   → USART1_IRQHandler
     → HAL_UART_IRQHandler
       → uart_rx_handler(byte)       ← UART 状态机
         → 找 0xAA → 收 8 字节 → 校验 CRC
           → MotorMsg_OnFrameReceived(MSG_CH_UART, payload)
             → 同上

③ Motor_Loop 每 1ms：
   → MotorMsg_PollCommand(&cmd)
     → g_new_frame 为真时返回解码后的指令
       → cmd.mode / cmd.target / cmd.kp / cmd.ki
```

**发送路径（电机状态 → 上位机）：**

```
① Motor_Loop 每 1ms：
   → MotorMsg_UpdateStatus(角度, 速度, Vq)
     → 编码到 g_tx_payload
    
   → MotorMsg_TxStatus()
     → CANProto_SendPayload(g_tx_payload)  ← 总是发
     → if (UART模式) UARTProto_SendPayload(g_tx_payload)
```

### 5.3 双模切换

```c
// motor_msg.c
static uint32_t g_last_can_rx = 0;

void MotorMsg_OnFrameReceived(MotorMsg_Channel_t ch, const uint8_t data[8]) {
    if (ch == MSG_CH_CAN) {
        g_last_can_rx = HAL_GetTick();  // 记录 CAN 最后收帧时间
    }
    // ... 解码 ...
}

// 判断当前通信模式
uint8_t MotorMsg_IsCANMode(void) {
    return (HAL_GetTick() - g_last_can_rx) < 500;  // 500ms 超时
}
```

| 模式 | 条件 | CAN 自定义协议 | UART 自定义协议 | VOFA+ 调试 |
|---|---|---|---|---|
| CAN 模式 | 500ms 内收到过 CAN 帧 | ✓ 发 | ✗ 停发 | ✓ 全速发 |
| UART 模式 | 超过 500ms 没收 CAN | ✓ 发（可共存） | ✓ 发 | ✗ 停发 |

## 6. 龙伯格观测器（完整链路）

### 6.1 它解决什么

编码器读到的角度中混杂了噪声（I2C 通信噪声、量化误差、振动）。

你原来的做法——差分法：

```
speed = (angle_now - angle_last) × frequency × 6
```

如果角度有 ±1° 的噪声，在 1kHz 控制频率下速度噪声 = ±6000°/s = ±1000rpm。速度环看到这么大的噪声波动，输出会剧烈抖动。

龙伯格观测器的做法：

```
内部维护一个"模型"，模型自己会推演位置和速度
用实测角度去"修正"模型的推演结果
模型输出的位置和速度天然平滑（就像一个有惯性的滤波）
```

### 6.2 数学模型

**二阶状态空间模型：**

```
状态向量 x = [x1  ]    x1 = 估计位置 (度)
             [x2]      x2 = 估计速度 (rpm)

每个控制周期（Ts = 1/1000 = 0.001s 做两件事：

① 预测（先验估计）——用物理模型推演
  x1_k+1 = x1_k + Ts × x2_k × 6   ← 位置增量 = 速度 × 6(deg/s per rpm) × Ts
  x2_k+1 = x2_k                     ← 速度不变（匀速假设）

② 校正（后验修正）——用实测角度纠偏
  error = y_k - x1_k                ← y_k = 实测角度
  x1_k+1 += l1 × error              ← 位置偏差按 l1 比例修正
  x2_k+1 += l2 × error              ← 速度偏差按 l2 比例修正
```

### 6.3 完整代码

```c
// Lib/Src/observer_luenberger.c

// 内部状态
typedef struct {
    float x1_hat;   // 估计位置 (deg)
    float x2_hat;   // 估计速度 (rpm)
    float l1, l2;   // 校正增益
    float Ts;       // 采样周期 (s)
    float x2_max;   // 速度限幅
} ObserverLuenbergerCtx_t;

// 核心更新函数——每 1ms 调一次
static void luenberger_update(void *ctx, float raw_angle_deg)
{
    ObserverLuenbergerCtx_t *c = (ObserverLuenbergerCtx_t *)ctx;

    // 误差 = 实测 - 估计（取最短路径，不是简单减法）
    float error = ANGLE_limit(raw_angle_deg - c->x1_hat, 360.0f, -180.0f, 180.0f);

    // 预测 + 校正（合在一起写了）
    // rpm × 6 = deg/s, deg/s × Ts = deg
    c->x1_hat += c->Ts * c->x2_hat * 6.0f + c->l1 * error;
    c->x1_hat  = ANGLE_limit(c->x1_hat, 360.0f, 0.0f, 360.0f);

    c->x2_hat += c->l2 * error;
    c->x2_hat  = DATA_limit(c->x2_hat, -c->x2_max, c->x2_max);
}
```

### 6.4 调用链路

```
main.c 初始化：
```

## 7. FOC 控制流水线

### 7.1 单周期流水线

每 1ms，`Motor_Loop` 执行以下步骤：

```
① FOC_UpdateSensor(&Motor)
   └─→ sensor->read_angle() → observer->update() → get_position/get_velocity

② FOC_ReadCurrents(&Motor)          [封存，恒输出 0]
   └─→ 读 ADC → Clarke 变换 → Park 变换 → Id / Iq
        （当前无电流反馈，全部返回 0）

③ 控制环（根据模式选执行）：
   ┌─ 位置模式：FOC_PosCtrl(&Motor) + FOC_SpdCtrl(&Motor)
   │    位置 PD → 目标速度 → 速度 PI → Uq
   │
   ├─ 速度模式：FOC_SpdCtrl_Ext(&Motor)
   │    速度 PI（独立的 PID 参数）→ Uq
   │
   ├─ 待机模式：什么都不做（不调 FOC_Output）
   │
   └─ 校准模式：FOC_Output 中检测到 calib_flag, 自动注入 Ud=4V

④ FOC_Output(&Motor)
   └─→ 电角度前馈补偿
     └─→ (Ud, Uq) 矢量限幅（防止过调制）
       └─→ InvPark 变换：d-q → α-β
         └─→ InvClarke SVPWM：α-β → 三相电压
           └─→ 归一化 [0,1] → motor->set_duty()
```

### 7.2 关键数学变换

**反 Park 变换（d-q → α-β）：**

```
Ualpha = Ud × cos(θ) - Uq × sin(θ)
Ubeta  = Uq × cos(θ) + Ud × sin(θ)

其中 θ = 电角度 + 前馈补偿角度
```

**SVPWM（零序分量注入法）：**

```
① 用反 Clarke 算出三相电压（不含直流偏置）
② 找三相中的 Vmax 和 Vmin
③ Vzero = (Vmax + Vmin) / 2    ← 零序分量
④ Va -= Vzero; Vb -= Vzero; Vc -= Vzero;  ← 每相减去零序
⑤ 再叠加 Udc/2 偏置，使范围到 [0, Udc]
⑥ 归一化到 [0, 1] 输出给 PWM

等价于经典 SVPWM，但不需要扇区判断和切换时间计算。
直流利用率 ~100%（对比 SPWM 的 86.6%）。
```

### 7.3 电角度前馈补偿

```
问题：从 AS5600 采样到 PWM 输出生效，总共延迟 ~210μs
      高速时（比如 2000rpm, 7 极对）, 转子在此期间转过：
      2000 × 7 × 6 × 0.00021 = 17.6° 电角度
      如果不补偿，电压矢量滞后转子 17.6°，部分电压跑到 d 轴

补偿方法：
  FOC_Output 中，先用当前速度算出补偿角度
  加到电角度上再做反 Park 变换
  
代码（Foc.c）：
  float angle_advance = speed × pole_pairs × 6 × ANGLE_COMP_DELAY_S;
  float comp_elec_angle = foc->elec_angle + angle_advance;
  FOC_Math_InvPark(Ud, Uq, comp_elec_angle * DEG_TO_RAD, ...);
```

## 8. 安全防护链

### 8.1 三层防护

```
第一层：通信超时（软件）
  位置/速度模式下 100ms 没收指令 → 自动待机关断

第二层：异常中断（硬件+软件）
  NMI / HardFault / BusFault / MemManage / UsageFault
  全部做的第一件事：PB1 拉低（关 MP6541）

第三层：独立看门狗（硬件）
  2s 不喂狗 → MCU 自动复位
```

### 8.2 看门狗配置

```c
static void IWDG_Init(void)
{
    // ① 开启 LSI 时钟
    RCC->CSR |= RCC_CSR_LSION;
    while (!(RCC->CSR & RCC_CSR_LSIRDY));

    // ② 解锁
    IWDG->KR = 0x5555U;

    // ③ 预分频 /256: 40kHz / 256 = 156.25Hz
    IWDG->PR = 0x06U;

    IWDG->KR = 0xAAAAU;   // 刷新

}
```

## 9. PID 时间归一化

### 9.1 区别

```c
// ❌ 你原来的写法——积分累加不乘 dt，Ki 值依赖频率
pid->integral += error;
output = kp * error + ki * integral + kd * derivative;

// ✅ 现在的写法——积分乘 dt，Ki 值与频率无关
pid->integral += error * dt;     // dt = 1/rate
output = kp * error + ki * integral + kd * (differential / dt);
```

### 9.2 好处

如果你把 FOC_RATE_HZ 从 1000Hz 改成 500Hz：

- **旧的写法**：积分累加速率减半，Ki 效果实际翻倍，要重新调参
- **现在的写法**：`integral += error × dt` 中 dt 也翻倍了，Ki 效果完全不变

### 9.3 Derivative-on-Measurement

```c
// 旧写法——微分项 = Kd × (error - last_error)
// 目标值突变时 error 跳变 → 微分冲击
pid->differential = error - last_error;

// 新写法——微分项 = Kd × Δ测量值
// 目标值突变不影响微分项，只有测量值变化才会产生微分作用
pid->differential = measure_error;  // 当前位置 - 上次位置
// 位置环中：传入 -angle_delta 起阻尼作用
float angle_delta = mech_angle - last_mech_angle;
PID_Calc(&PosPID, error, -angle_delta);
```

## 10. static 隐藏内部状态

### 10.1 原则

```c
// 头文件中只放函数声明
// .c 文件中用 static 隐藏所有内部变量和辅助函数

// ❌ 不好——头文件中暴露内部变量
// drv_adc.h:
extern int16_t adc_dma_buf[3];  // 谁都能改

// ✅ 好——头文件只放 API 声明
// drv_adc.h:
void ADC_ReadPhaseCurrents(ADC_PhaseCurrents_t *currents);

// drv_adc.c:
static int16_t s_adc_dma_buf[3] = {0};    // 外部不可见
static int16_t s_adc_snapshot[3] = {0};
```

### 10.2 好处

- **可控的访问入口**：要读 ADC 数据只能通过 `ADC_GetRawCurrents()`，而不是直接读写数组
- **重构安全**：内部实现改了（比如数组大小变了），不影响外部调用代码
- **命名空间干净**：IDE 提示时不会看到一堆内部变量

## 总结：你应该带走的核心技能

| 技能 | 重要性 | 一句话说明 |
|---|---|---|
| 抽象接口模式 | ⭐⭐⭐ | 用 struct{函数指针; void *ctx} 把"干什么"和"怎么干"分离 |
| 四层架构 | ⭐⭐⭐ | APP/DRV/BSP/LIB，上层调下层，下层不能调上层 |
| 工厂函数 | ⭐⭐⭐ | `XXX_Create(参数) → 接口结构体`，对象的构造器 |
| 回调注册 | ⭐⭐ | 中断中不写业务逻辑，用 `RegisterCallback(func)` 挂上去 |
| 消息总线 | ⭐⭐ | 所有通信数据统一入口、统一解码，业务不需要知道来源 |
| static 封装 | ⭐⭐ | 内部变量用 static 隐藏，只通过 API 函数暴露 |
| 时间归一化 | ⭐⭐ | `integral += error × dt`，Ki 不再跟频率绑定 |
| 龙伯格观测器 | ⭐⭐ | 内部模型预测 + 实测值校正 → 平滑的位置和速度 |
| FOC 数学 | ⭐ | 反 Park → SVPWM 零序注入 → 归一化输出 |
| 前馈补偿 | ⭐ | 用当前速度推算延迟期间的角度偏移，提前补偿到输出角度 |

> **核心一条：** 以后再写代码，先想"这个功能将来会不会换硬件实现？"。如果会 → 用接口模式。
> 接口模式就三行——一个结构体、几个函数指针、一个 void *ctx。你完全能掌握。
