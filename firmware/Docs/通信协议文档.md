## 1. 协议总览

### 1.1 双通信介质

PicoFOC 支持 **CAN** 和 **UART** 两种物理通信介质，两者独立运行、共用同一套 payload 格式。

| 介质 | 参数 | MCU 引脚 |
|------|------|---------|
| CAN | 1 Mbps，标准帧（11 位 ID），8 字节数据 | PA11(RX), PA12(TX) |
| UART | 115200 8N1 | PA10(RX), PA9(TX) |

### 1.2 统一 8 字节 Payload 设计

CAN 和 UART 的**核心数据格式完全一致**——8 字节 payload 结构相同，编解码共用 `motor_msg.c` 同一套代码：

```
上位机 ──→ 电机 : [8 字节控制帧]   (RX 方向)
电机   ──→ 上位机 : [8 字节状态帧]   (TX 方向)
```

| 介质 | RX 控制帧 | TX 状态帧 |
|------|----------|-----------|
| CAN | 裸 8 字节（ID=0x000+电机ID） | 裸 8 字节（ID=0x100+电机ID） |
| UART | `[0xAA][0x08][payload][CRC16]` | 同左 |

## 2. RX 控制帧（上位机 → 电机）

### 2.1 8 字节 Payload 布局

```
偏移:  [0]        [1][2][3][4]       [5][6]         [7]
      ┌──────────┬──────────────────┬──────────────┬──────────┐
      │  mode    │     target       │   kp_raw     │ kd_raw   │
      │  uint8   │   float32 LE     │  uint16 LE   │  uint8   │
      └──────────┴──────────────────┴──────────────┴──────────┘
```

### 2.2 mode — 运行模式（byte [0]）

| 值 | 名称 | 说明 |
|----|------|------|
| 0 | STANDBY | 待机，关断驱动芯片，PWM 停止，PID 积分清零 |
| 1 | TORQUE | 力矩模式（预留，未实现） |
| 2 | SPEED | 速度模式（独立速度 PI 环，使用 SpdPID_Ext） |
| 3 | POSITION | 位置模式（串级：位置 PD → 速度 PI） |
| 4 | CALIBRATE | 电角度自校准 |

> **边界处理：** 在 CAN/UART 协议层（收发回调中）做 `data[0] <= 4` 检查，mode 值 > 4 的帧**静默丢弃**。

### 2.3 target — 目标值（bytes [1..4]）

IEEE 754 **单精度浮点数、小端字节序**。单位取决于当前模式：

| 模式 | 物理含义 | 输入单位 | 内部换算 |
|------|---------|----------|---------|
| SPEED | 目标机械角速度 | **rad/s** | `rpm = target × 9.5493` |
| POSITION | 目标机械角度 | **rad** | `deg = target × 57.2958` |
| CALIBRATE | 忽略 | — | — |
| STANDBY | 忽略 | — | — |

> **边界处理：** 解码后检查 IEEE 754 指数位（`0x7F800000`），NaN/Inf 自动替换为 0.0。

**常用角度换算表：**

| 角度 | 弧度 (float32) | 编码 HEX (LE) |
|------|---------------|---------------|
| 0° | 0.0 | `00 00 00 00` |
| 45° | 0.785398 | `49 0F C9 3F` |
| 90° | 1.570796 | `DB 0F C9 3F` |
| 180° | 3.141593 | `DB 0F 49 40` |
| 270° | 4.712389 | `DB 0F 96 40` |
| 280° | 4.886922 | `AA 61 9C 40` |
| 320° | 5.585054 | `C2 B8 B2 40` |
| 340° | 5.934119 | `4E E4 BD 40` |
| 360° | 6.283185 | `DB 0F C8 40` |

### 2.4 kp_raw — 比例增益（bytes [5..6]）

uint16 **小端**，**同时**设置位置环 Kp 和速度环 Kp。

| 属性 | 值 |
|------|-----|
| 解码公式 | `kp_float = raw × 0.00015259` |
| 编码公式 | `raw = round(kp_float / 0.00015259)` |
| 系数推导 | `10.0 / 65535 ≈ 0.00015259` |
| kp 范围 | **0.0 ~ 10.0** |
| raw 范围 | 0 ~ 65535 |
| 分辨率 | ~0.00015 |

**常用值速查：**

| kp_float | raw | HEX (LE) |
|----------|-----|----------|
| 0.0 | 0 | `00 00` |
| 0.01 | 66 | `42 00` |
| 0.05 | 328 | `48 01` |
| 1.0 | 6554 | `9A 19` |
| 3.0 | 19661 | `4D 4C` |
| **5.0** | **32768** | **`00 80`** |
| 10.0 | 65535 | `FF FF` |

### 2.5 kd_raw — 微分/积分增益（byte [7]）

一个 uint8 **同时编码**位置环 Kd 和速度环 Ki。

| 属性 | 值 |
|------|-----|
| 解码公式 | `kd_float = raw × 0.00392157`（写 pos_kd 和 spd_ki） |
| 编码公式 | `raw = round(kd_float / 0.00392157)` |
| 系数推导 | `1.0 / 255 ≈ 0.00392157` |
| kd/ki 范围 | **0.0 ~ 1.0** |
| raw 范围 | 0 ~ 255 |
| 分辨率 | ~0.00392 |

**常用值速查：**

| kd/ki_float | raw | HEX |
|-------------|-----|-----|
| 0.0 | 0 | `00` |
| 0.004 | 1 | `01` |
| 0.01 | 3 | `03` |
| 0.1 | 26 | `1A` |
| 0.5 | 128 | `80` |
| 1.0 | 255 | `FF` |

> ⚠️ **已知限制：** Kd 和 Ki 共用同一字节，无法独立设置。调位置环阻尼的同时会改变速度环积分，反之亦然。

### 2.6 CAN 控制帧

```
CAN ID = 0x000 + 电机ID  （标准帧，11 位）
默认（电机ID=1）：ID = 0x001
```

8 字节 payload 直接放入 CAN 数据场发送，**无额外帧头**。

### 2.7 UART 控制帧（完整 12 字节）

```
偏移: [0]    [1]    [2..9]          [10..11]
     ┌──────┬──────┬────────────────┬────────────┐
     │ 0xAA │ 0x08 │ 8-byte payload │ CRC16-CCITT│
     │ 帧头  │ 长度  │ （同 CAN）     │  小端       │
     └──────┴──────┴────────────────┴────────────┘
```

- **帧头（SOF）：** `0xAA`，用于接收状态机同步
- **长度字段：** 固定 `0x08`
- **CRC16-CCITT：** 对 SOF + LEN + 8 字节 payload 共 **10 字节**计算，小端存放
  - 多项式：`0x1021`，初始值：`0xFFFF`
  - 参考实现见第 [7 节](#7-crc16-ccitt-实现)
- **接收流程：** UART 中断 → 逐字节状态机 → 找 `0xAA` → 读长度 → 收 8 字节 payload → 收 2 字节 CRC → 校验 → 通过则解码
- **错误处理：** CRC 失败、长度不为 `0x08`、mode > 4 → 静默丢弃，状态机复位

## 3. TX 状态帧（电机 → 上位机）

### 3.1 8 字节 Payload 布局

```
偏移: [0..1]         [2..3]         [4..5]         [6..7]
     ┌──────────────┬──────────────┬──────────────┬──────────────┐
     │  位置 raw    │  速度 raw    │  Vq raw      │   保留       │
     │   int16 LE   │   int16 LE   │  int16 LE    │   = 0x0000  │
     └──────────────┴──────────────┴──────────────┴──────────────┘
```

编码通式：`raw = (int16_t)(物理量 × 编码系数)`

### 3.2 位置反馈（bytes [0..1]）

| 属性 | 值 |
|------|-----|
| 编码公式 | `raw = pos_rad × 834.4` |
| 解码公式 | `pos_rad = raw / 834.4` → `pos_deg = pos_rad × 57.2958` |
| 系数推导 | `32767 / (12.5 × π) ≈ 834.4` |
| 可编码范围 | **±39.27 rad（≈ ±2250°，约 6.25 圈）** |
| 分辨率 | **0.0012 rad ≈ 0.069°** |

### 3.3 速度反馈（bytes [2..3]）

| 属性 | 值 |
|------|-----|
| 编码公式 | `raw = speed_rads × 131.07` |
| 解码公式 | `speed_rads = raw / 131.07` → `rpm = speed_rads × 9.5493` |
| 系数推导 | `32767 / 250 ≈ 131.07` |
| 可编码范围 | **±250 rad/s（≈ ±2387 rpm）** |
| 分辨率 | **0.0076 rad/s ≈ 0.073 rpm** |

> 量程变更历史：2026-07-25 从 `655.34`（±477.5 rpm）改为 `131.07`（±2387 rpm）。

### 3.4 Vq 反馈（bytes [4..5]）

| 属性 | 值 |
|------|-----|
| 编码公式 | `raw = vq × 819.175` |
| 解码公式 | `vq = raw / 819.175` |
| 系数推导 | `32767 / 40 ≈ 819.175` |
| 可编码范围 | **±40 V** |
| 分辨率 | **0.00122 V** |

> 实际母线 12V，Vq 限幅在 ±12V，远在量程内，无饱和风险。

### 3.5 CAN 状态帧

```
CAN ID = 0x100 + 电机ID（标准帧，11 位）
默认（电机ID=1）：ID = 0x101
```

### 3.6 UART 状态帧

格式与 [2.7 UART 控制帧](#27-uart-控制帧完整-12-字节) 完全相同：`[0xAA][0x08][payload][CRC16 LE]`。

### 3.7 发送策略（双模自动切换）

状态帧每 1ms 发一次，CAN 和 UART 的发送策略不同：

```
每 1ms 控制周期：
  CANProto_SendPayload(payload)    ← 始终发送（CAN 总线 1kHz）
  if (UART 模式)                    ← 仅 500ms 内没收到 CAN 帧时
    UARTProto_SendPayload(payload)
```

**模式判定（500ms 超时）：**

| 模式 | 条件 | CAN 状态帧 | UART 自定义协议 | VOFA+ 调试 |
|------|------|-----------|---------------|-----------|
| **CAN 模式** | 最近 500ms 内收过 CAN 帧 | 1kHz ✓ | 停发 ✗ | 全速 ✓ |
| **UART 模式** | 超过 500ms 没收 CAN | 1kHz ✓ | 1kHz ✓ | 停发 ✗ |

## 4. VOFA+ 调试通道

### 4.1 帧格式

独立于自定义协议之上，与自定义协议**共用同一根 UART 线**。

```
[N × float32 (4N bytes)] [0x00, 0x00, 0x80, 0x7f]
  channel data              VOFA+ just-float 帧尾
```

- N = 8 通道，共 **36 字节/帧**
- 帧尾是 IEEE 754 的 +Inf（解释为 float 时 ≈ 1.1755e-38 非规范化数），VOFA+ 用它识别帧结束
- **同线共存：**
  - 自定义协议以 `0xAA` 开头 → VOFA+ 看到 `0xAA` 当无效浮点数忽略
  - VOFA 帧不以 `0xAA` 开头 → 自定义协议上位机（按 CRC 过滤）丢弃
  - `uart_tx_busy` 互斥锁防止两者同时发送

### 4.2 通道映射

| 通道 | 变量 | 单位 |
|------|------|------|
| ch0 | `Motor.mech_angle` | °（机械角度，观测器滤波后） |
| ch1 | `Motor.target_angle` | °（目标角度） |
| ch2 | `Motor.speed` | rpm（实际转速） |
| ch3 | `Motor.target_speed` | rpm（目标转速） |
| ch4 | `Motor.Uq` | V（交轴电压） |
| ch5 | `(float)MotorMsg_GetLastMode()` | —（运行模式 0~4） |
| ch6 | `MotorMsg_GetLastTarget()` | rad/rpm/Nm（最近指令目标值） |
| ch7 | `0.0f` | —（保留） |

### 4.3 发送条件

- **仅 CAN 模式**下发送（UART 模式停发，让出带宽给自定义协议）
- 由 `main.c` 的 `while(1)` 循环全速驱动
- 受 `uart_tx_busy` 互斥锁限制，实际约 1~2kHz

uint16_t CRC16_CCITT(const uint8_t *data, uint32_t len)
{
    uint16_t crc = 0xFFFF;
    for (uint32_t i = 0; i < len; i++)
    {
        crc = (crc << 8) ^ crc16_table[((crc >> 8) ^ data[i]) & 0xFF];
    }
    return crc;
}
```

> 位运算版本（适用于查表空间受限的场景）：
> ```c
> uint16_t CRC16_CCITT(const uint8_t *data, uint32_t len) {
>     uint16_t crc = 0xFFFF;
>     for (uint32_t i = 0; i < len; i++) {
>         crc ^= (uint16_t)data[i] << 8;
>         for (int j = 0; j < 8; j++)
>             crc = (crc & 0x8000) ? (crc << 1) ^ 0x1021 : (crc << 1);
>     }
>     return crc;
> }
> ```

## 附录：完整发送流程速查

### 上位机发指令（控制帧）

```
① 决定模式、目标值、Kp、Kd → 填写 8 字节 payload
② CAN 方式：发到 ID = 0x000 + 电机ID（默认 0x001）
③ UART 方式：
   帧 = [0xAA][0x08][payload][CRC16_CCITT(10B) 小端]
   发到 UART（115200 8N1）
```

### 电机回传数据（状态帧，自动 1kHz）

```
① 电机每 1ms 编码 tx_payload：
     [0..1] = int16(g_pos_rad × 834.4)
     [2..3] = int16(g_spd_rads × 131.07)
     [4..5] = int16(g_vq × 819.175)
     [6..7] = 0x0000
② CAN 方式：ID = 0x100 + 电机ID（默认 0x101），始终发送
③ UART 方式：帧头封装同上，仅 UART 模式发送
④ VOFA+（仅 CAN 模式）：8×float + 帧尾，36 字节
```
